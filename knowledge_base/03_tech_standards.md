# 技术开发规范

本规范适用于星辰科技研发中心所有后端、前端、算法和测试工作。

## 1. 技术栈基线

- 后端：Python 3.11 及以上，FastAPI 0.115 及以上。
- 工作流编排：LangGraph 1.x。
- 大模型调用：DeepSeek，通过 OpenAI 兼容接口访问，模型标识为 deepseek-chat。
- 向量数据库：Chroma，本地持久化目录为 data/chroma。
- 中文 Embedding：BAAI/bge-small-zh-v1.5。
- 测试：pytest；外部模型调用必须使用 Mock。

## 2. Git 与分支

- 主分支为 main，集成分支为 develop。
- 功能开发从 develop 创建 feature/<简短描述> 分支。
- 禁止直接向 main 推送代码。
- 提交信息遵循 Conventional Commits，例如 feat:、fix:、docs:、test:、refactor:。
- 合并请求至少需要 1 名同组工程师评审；核心模块需要 2 名评审人。
- 合并前必须通过全部自动化测试和静态检查。

## 3. 代码质量

- 公共函数和复杂逻辑必须写文档字符串，说明输入、输出和异常。
- 单个函数原则上不超过 50 行；超过时应拆分。
- 禁止在代码中硬编码 API Key、数据库密码或客户数据。
- 密钥统一通过环境变量或 .env 注入，.env 不得提交到 Git。
- 新增依赖须说明用途并提交锁文件；优先选择维护活跃、许可证清晰的库。

## 4. 测试要求

- 新增核心逻辑必须补充单元测试。
- 调用大模型、外部 HTTP 接口的测试必须使用 Mock，不得消耗真实 API 额度。
- 测试应覆盖正常路径、参数校验失败、外部依赖异常和无结果场景。
- 核心模块行覆盖率不低于 70%。
- 提交前在项目根目录执行 pytest -v，确保全部通过。

## 5. API 设计

- 使用 REST 风格，请求和响应均为 UTF-8 JSON。
- 健康检查接口为 GET /health，返回 {"status":"ok"}。
- 问答接口为 POST /chat，请求体包含 question，响应包含 answer 和 sources。
- 错误响应统一使用 {"detail":"..."}，不返回堆栈或内部路径。
- 新增对外接口应带版本前缀，例如 /api/v1。

## 6. 日志与可观测性

- 日志不得包含 API Key、完整问题原文中的敏感信息或客户个人信息。
- 外部调用失败时记录异常类型和请求标识，不记录完整请求体。
- 生产服务须提供健康检查和结构化日志。

## 7. RAG 开发约定

- 知识库文档必须包含 doc_id、title、department、access_scope 等元数据。
- 检索结果必须随答案返回来源，便于审计。
- 当检索结果低于相关度阈值时，应明确回答“知识库中未找到相关依据”，不得编造。
- 提示词中要求模型仅依据检索片段回答。
- 文档更新后须重新执行知识库初始化命令。

## 8. 发布与故障处理

- 发布窗口为工作日 14:00—17:00，紧急修复除外。
- P0 故障（服务完全不可用）须在 15 分钟内响应；P1 故障须在 1 小时内响应。
- 回滚须使用上一稳定版本，并在故障复盘文档中记录原因和改进项。
